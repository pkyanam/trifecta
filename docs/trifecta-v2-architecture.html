Trifecta v2 — Cloud Sandbox Architecture

Firecracker microVM sandboxes · Control plane on ECS Fargate · Pairing-based multi-client access

Control Plane

  • • ECS Fargate — no KVM needed, serverless
  • • Existing Effect-TS server (Bun)
  • • Provider SPI unchanged — new Firecracker driver
  • • Auth pairing flow identical to v1
  • • DynamoDB for sessions + user state

Sandbox Layer

  • • EC2 c6i.4xlarge — nested virt (KVM)
  • • Firecracker microVMs: Alpine + codex CLI
  • • Snapshot pools: <100ms VM provision
  • • vsock comms — no network attack surface
  • • Workspaces: S3 pull → tmpfs → S3 push

Security Model

  • • Each VM: own kernel (KVM boundary)
  • • No cross-VM networking — NAT-only egress
  • • Ephemeral disks (tmpfs) — destroyed on stop
  • • Pairing tokens: one-time use, scoped
  • • WSS tokens: short-lived, per-connection
